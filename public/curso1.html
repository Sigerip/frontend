Contexto da atividade

O objetivo principal é criar um infográfico que comunique um insight relevante, definido pelo próprio aluno, sobre mortalidade e projeções atuariais, usando os dados do OI Atuarial. Mas sem recair na armadilha de aceitar a primeira resposta da IA ou de criar um gráfico bonito sem base sólida. O processo precisa ser auditável: cada conclusão deve ter uma evidência clara no notebook, seja uma tabela, um cálculo ou um gráfico. O infográfico deve ser fiel aos dados, claro para um público não técnico e visualmente atraente, mas sem exagerar nas conclusões.

Para isso cada aluno vai passar por 7 etapas, e é incentivado a executar o processo sugerido abaixo já pensando em variações que possam ser testadas. O objetivo é aprender fazendo, mas também aprender sobre o processo, para que possamos documentar um caminho recomendado para criar infográficos com IA e dados atuariais.

Resultado esperado: cada aluno deve sair com um notebook funcional, uma análise inicial, um relatório curto de insights e um infográfico no NotebookLM.

Dados disponíveis

O ponto de partida são os dados e visualizações do OI Atuarial . A ideia não é que todo mundo analise tudo. Cada participante deve escolher um recorte viável, entender bem esse recorte e transformá-lo em uma história clara.

O site e a API indicam quatro conjuntos principais de dados:

1 Escolher os dados no OI Atuarial

Acessem o OI Atuarial e explorem as páginas disponíveis. Escolham um recorte simples para começar: Brasil ou uma UF, uma faixa etária, um sexo, um período histórico, um ano projetado ou uma comparação entre modelos.

Tentem transformar o recorte em uma pergunta de trabalho. Exemplos:

  • Como a expectativa de vida varia entre homens e mulheres?
  • Quais faixas etárias concentram mudanças relevantes na mortalidade?
  • O que as projeções sugerem para 2030, 2050 ou 2070?
  • Os modelos de projeção contam histórias diferentes?
  • Há diferenças relevantes entre Brasil, regiões e UFs?
  • Alguma região ou UF chama atenção quando comparada ao Brasil?

Ao escolher a pergunta, registrem também por que ela parece interessante para virar infográfico. Isso ajuda a não perder o fio narrativo no meio da análise.

2 Baixar os dados e subir no Google Colab

Há duas formas possíveis de levar os dados para o Colab. Escolha a mais confortável. O importante é que o notebook registre claramente de onde os dados vieram.

Opção A: baixar pelo site e subir no Colab

  1. No OI Atuarial, escolha a tabela ou visualização que deseja analisar.
  2. Use a opção de baixar ou exportar dados, quando disponível.
  3. Salve o arquivo em formato CSV ou Excel.
  4. No Google Colab, clique no ícone de arquivos e faça upload do arquivo baixado.
  5. Carregue o arquivo com pandas.
Python (Opção A) 
import pandas as pd

# Se o arquivo for CSV:
df = pd.read_csv("nome_do_arquivo.csv")

# Se o arquivo for Excel:
df = pd.read_excel("nome_do_arquivo.xlsx")

df.head()

Esta opção é boa para trabalhar com um recorte mais controlado e visualmente escolhido no próprio site.

Opção B: carregar pela API no Colab

  1. Acesse a página de solicitação de token .
  2. Solicite o token e verifique o e-mail.
  3. No Colab, use o código abaixo ou o arquivo colab_carregar_dados_oiatuarial.py.
Python (Opção B) 
import getpass
import requests
import pandas as pd

BASE_URL = "https://backend-weld-five-44.vercel.app/oiatuarial_api"
token = getpass.getpass("Cole seu token da API OI Atuarial: ")

def carregar_oiatuarial(endpoint):
    url = f"{BASE_URL}/{endpoint}"
    headers = {"Authorization": f"Bearer {token}"}
    response = requests.get(url, headers=headers, timeout=60)
    response.raise_for_status()
    data = response.json()
    return pd.read_parquet(data["url_download"])

dados_mortalidade = carregar_oiatuarial("dados_mortalidade1")
projecoes = carregar_oiatuarial("projecoes")
metricas_erro = carregar_oiatuarial("metricas_erro")
nacoes_unidas = carregar_oiatuarial("nacoes_unidas")

dados_mortalidade.head()

Esta opção é boa para testar um fluxo mais automatizado e reproduzível, especialmente se você quiser comparar vários recortes.

3 Produzir uma análise com IA de forma auditável

Use o Gemini no Colab como parceiro de análise, mas não aceite conclusões sem verificar o código, as tabelas intermediárias e os gráficos. A IA acelera o trabalho, mas você precisa saber explicar o que aconteceu.

Regra prática: toda conclusão deve ter uma evidência visível no notebook: uma tabela, um cálculo, um gráfico ou uma célula de código que possa ser revisada.

Prompt Sugerido para Iniciar:

Você é um analista de dados atuariais e um consultor de visualização de dados. Analise o DataFrame carregado neste notebook com foco em Brasil. Faça: 1. explique o que cada coluna parece representar; 2. proponha 5 perguntas de análise que possam virar um infográfico; 3. indique quais colunas usar em cada pergunta; 4. gere código pandas simples para responder à pergunta mais promissora; 5. crie tabelas intermediárias que permitam auditar os resultados; 6. gere 2 visualizações simples com matplotlib ou seaborn. Responda em português do Brasil e não tire conclusões sem indicar a evidência usada.

Prompt para Aprofundar uma Pergunta Específica:

Quero investigar a seguinte pergunta: "Como a expectativa de vida varia entre homens e mulheres ao longo do tempo?" Gere uma análise auditável em Python com pandas. Inclua: - filtros aplicados; - tabela-resumo; - cálculos de diferença absoluta e percentual, quando fizer sentido; - gráficos simples; - interpretação dos resultados; - limitações da análise. Diferencie dados observados, projeções e interpretação.

Depois que o Gemini gerar código, rode célula por célula. Se algo parecer estranho, peça explicação, altere filtros e confira os resultados. O curso é também um teste de como trabalhar com IA sem perder controle analítico.

4 Gerar um relatório final com os insights

Depois da análise, produza um relatório curto. Esse relatório será a fonte principal para o NotebookLM. Ele deve ser claro o bastante para que alguém que não abriu o notebook entenda a história dos dados.

Estrutura recomendada:

  • título;
  • pergunta orientadora;
  • mensagem central;
  • 3 a 5 achados principais;
  • evidências numéricas;
  • gráficos ou tabelas usados;
  • limitações;
  • recomendação de narrativa visual.

Prompt Sugerido para gerar o relatório:

Transforme a análise deste notebook em um relatório curto para orientar a criação de um infográfico. O relatório deve conter: - título; - pergunta orientadora; - mensagem central; - principais achados com números; - explicação dos dados usados; - limitações e cuidados de interpretação; - sugestões de estrutura visual para o infográfico; - glossário curto para termos técnicos, se necessário. Escreva em português do Brasil. Seja claro, sintético e fiel aos dados.

Para salvar o relatório no Colab:

Python (Salvar Relatório) 
texto_insights = """Cole aqui o relatório final revisado."""

with open("insights_oiatuarial.md", "w", encoding="utf-8") as f:
    f.write(texto_insights)

Antes de seguir, revise o relatório. Ele não deve ser apenas uma resposta copiada da IA. Ajuste termos, confira números e retire afirmações que não estejam apoiadas no notebook.

5 Baixar o relatório e subir no NotebookLM

Baixe o arquivo insights_oiatuarial.md gerado no Colab. Em seguida, crie um novo projeto no NotebookLM e envie esse arquivo como fonte.

Se achar útil, também pode subir fontes adicionais:

  • tabelas-resumo exportadas do Colab;
  • imagens dos gráficos exploratórios;
  • uma explicação curta sobre o significado das variáveis usadas;
  • notas sobre público-alvo, tom e mensagem desejada;
  • um pequeno glossário de termos técnicos.

O NotebookLM tende a funcionar melhor quando a fonte já contém uma história bem organizada. Por isso, o relatório de insights é uma peça importante do processo.

6 Gerar o infográfico no NotebookLM

No NotebookLM, peça primeiro alternativas de narrativa visual. Depois, escolha a melhor e peça uma versão mais refinada. O ideal é iterar, não aceitar a primeira resposta.

Prompt Sugerido para o NotebookLM:

Crie um infográfico em português do Brasil com base nas fontes deste projeto. Objetivo: comunicar a principal história encontrada nos dados de mortalidade e projeções da OI Atuarial. O infográfico deve: - ter um título forte e informativo; - destacar 3 achados principais com números; - separar dados observados, projeções e interpretação; - incluir uma nota curta sobre limitações; - usar linguagem acessível para público não técnico; - sugerir uma hierarquia visual clara, com blocos, chamadas e conclusão final. Antes da versão final, proponha 3 alternativas de narrativa visual e explique qual delas é mais forte.

Depois da primeira resposta, escolha uma direção e peça ajustes. Exemplos: deixar mais didático, tornar mais executivo, reduzir texto, destacar comparação regional, deixar as limitações mais visíveis ou reforçar a diferença entre observado e projetado.

Etapa 6 Checklist Passo a Passo
Gerar as 3 alternativas de infográfico
Analisar qual das abordagens geradas pelo NotebookLM conta melhor a história dos dados.

7 Refinar o infográfico

A primeira versão não precisa ser a final. Revise a fidelidade aos dados, a clareza da mensagem e a força visual. O objetivo é melhorar o processo, não apenas aceitar a primeira saída da ferramenta.

Prompt de Refinamento:

Revise o infográfico proposto. Verifique: - se a mensagem central está clara; - se os números estão fiéis ao relatório; - se há confusão entre dados observados e projeções; - se a linguagem está adequada para público não técnico; - se a estrutura visual pode ser simplificada. Proponha uma versão refinada, com título melhor, hierarquia mais clara e notas de cautela quando necessário.

Registre o que mudou entre a primeira versão e a versão refinada. Essa comparação ajuda a entender quais prompts e decisões melhoram o resultado.

Etapa 7 Checklist de Refinamento Critérios de Qualidade
O título comunica a mensagem central?
Os números batem com o relatório e com o notebook?
Está claro o que é dado observado e o que é projeção?
O infográfico evita conclusões causais exageradas?
A hierarquia visual ajuda o leitor a entender a história?
Há uma conclusão ou recomendação explícita?
O aluno consegue explicar como chegou ao resultado?

Como variar o processo

Cada aluno deve experimentar pelo menos uma variação. A ideia é que o curso gere aprendizado comparativo e discussões ricas de técnicas.

Algumas opções de variação:

  • mudar o prompt de análise para uma abordagem mais técnica, mais executiva ou mais jornalística;
  • usar apenas dados baixados do site, sem API;
  • usar a API para carregar mais dados e comparar múltiplos recortes;
  • comparar Brasil, regiões e UFs;
  • comparar sexo masculino e feminino;
  • comparar modelos de projeção;
  • focar em um ano projetado, como 2030, 2050 ou 2070;
  • subir no NotebookLM apenas o relatório final ou incluir também tabelas-resumo e gráficos;
  • pedir ao NotebookLM primeiro um briefing editorial e só depois o infográfico;
  • usar o Gemini para criticar o infográfico e propor uma segunda versão;
  • testar outra ferramenta de visualização ou geração visual e comparar com o NotebookLM.

Ao final, tente responder: qual variação melhorou o resultado? Qual só gerou mais trabalho? O que vale recomendar para um curso externo?

Critério central: o melhor resultado não é apenas o infográfico mais bonito. É aquele que combina clareza, fidelidade aos dados, boa narrativa visual e processo reproduzível.
